# AGENTS.md

## Project overview

devcap.app is a macOS menubar app that scans local git repositories and shows a commit worklog grouped by project and branch. The UI is SwiftUI (Swift 6), the git scanning logic is Rust, connected via C FFI.

- Deployment target macOS 14.0, Swift 6.0, Xcode 16+
- Core logic lives in the external crate `devcap-core` (`konradmichalik/devcap`, pinned by tag in `devcap-ffi/Cargo.toml`)
- The app is `LSUIElement` (no Dock icon), menubar-only via `MenuBarExtra`

## Structure

- `DevcapApp/Bridge/`: `DevcapBridge.swift` wraps the FFI calls (C string lifecycle, JSON decoding). `devcap.h` is generated by `cbindgen` and gitignored
- `DevcapApp/Models/`: `AppState` (`@MainActor ObservableObject`, scan logic, refresh timer, `@AppStorage` settings) and `DevcapData` (Codable models)
- `DevcapApp/Services/`: export, terminal launching, project sorting, web URL helpers
- `DevcapApp/Views/`: menubar popover, project tree rows, settings, about
- `DevcapAppTests/`: XCTest unit tests
- `devcap-ffi/`: Rust static library exposing `devcap_scan`, `devcap_default_author`, `devcap_free_string`. Uses `rayon` for parallel scanning
- `project.yml`: XcodeGen definition and source of truth. `DevcapApp.xcodeproj` is generated from it
- `docs/`: `DEVELOPMENT.md`, `RELEASE.md`

Data flow: `AppState` calls `DevcapBridge.scan()`, which calls `devcap_scan()` over FFI and decodes the returned JSON into `ProjectLog`, `BranchLog` and `Commit`. Rust emits `snake_case` keys (`commit_type`, `relative_time`), mapped in Swift via `CodingKeys`. Period values: `today`, `yesterday`, `week`, `7d`.

## Development commands

Requires the Rust toolchain and [XcodeGen](https://github.com/yonaskolb/xcodegen) (`brew install xcodegen`).

```bash
make ffi          # build the Rust static library (release)
make xcode        # regenerate the Xcode project from project.yml
make build        # ffi, xcode, then xcodebuild (Release)
make update-core  # cargo update -p devcap-core, then rebuild
make clean
```

The Xcode scheme runs `cargo build --release` as a pre-build script, so `Cmd+R` in Xcode also builds the FFI library. If `devcap-core` model fields change, update `DevcapApp/Models/DevcapData.swift` to match.

## Testing

```bash
cd devcap-ffi && cargo test
```

Swift unit tests live in `DevcapAppTests/` and run through the `DevcapApp` scheme in Xcode (or `xcodebuild test`). CI does not run tests, only the linters.

## Code style and linting

```bash
make lint         # lint-rust and lint-swift
make lint-rust    # cargo fmt --check, cargo clippy -- -D warnings
make lint-swift   # swiftlint lint --strict
```

- CI (`.github/workflows/lint.yml`) runs the same Rust and SwiftLint checks on every push
- Clippy denies `unwrap_used` and `todo`, warns on `expect_used` and `dbg_macro`
- SwiftLint (`.swiftlint.yml`) opts in to `force_unwrapping` among others. Line length warns at 150, function bodies at 50 lines, files at 400 lines

## Git workflow

- Commit format: `<type>: <description>` with `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`
- No co-author trailers
- Releases are built by `.github/workflows/release.yml` (see `docs/RELEASE.md`)
